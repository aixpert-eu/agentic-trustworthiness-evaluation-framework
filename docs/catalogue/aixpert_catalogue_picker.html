Applicability categories

Evidence is not the same as human input. Extra evidence may be repeated runs, tool traces, token probabilities, resource measurements or ratings. Participant responses are required for usability and cognitive load; judge–human agreement requires human reference ratings. Labeled datasets may be prepared in advance.
Multiple runs ≠ multiple agents. Input/output metrics assess a single agent’s responses; behaviour metrics assess its actions or repeated attempts. System measurements and evaluation-process metrics are cross-cutting. Generic scores may be applied to a multi-agent system’s final output when compatible data is supplied, but they do not measure coordination. Multi-agent-specific evaluators are not included in the committed framework. Local-only benchmark additions are excluded from this catalogue.

From an agent run to an assessment

The harness starts with a captured trajectory. An adapter converts the agent output into EvaluationInput ; an optional TaskDefinition supplies target answers, expected tool calls or task-specific checks. The registry selects applicable single-trajectory evaluators.

Missing labels cause metrics to be skipped. Individual evaluator failures are captured without stopping the rest of the report. Batch, reflective, survey and measurement-based metrics need separate evidence and orchestration.

Reading the results

Results include a score, explanation, success indicator and metadata. Where supported, metric-specific banding maps results to 0–4: Unacceptable, Below expectations, Adequate, Good and Excellent. Some metrics use binary checks; a single universal score threshold would be misleading.
